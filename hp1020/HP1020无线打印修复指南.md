# HP LaserJet 1020 Plus 无线打印"断电即失效" —— 修复记录

**状态**：已部署完成并验证通过（2026-09-28）
**环境**：Padavan（RT-N14U / MT7620，hiboy 版 3.4.3.9-099）路由器 USB 口 + 手机 PrintHand

---

## 一、问题根因

HP LaserJet 1020 / 1020 Plus 是**宿主型（GDI / ZJS）打印机**，机身只有 32KB ROM，**固件不在打印机里**。
每次通电后必须由外部把 `sihp1020.dl` 灌进打印机**内存**，断电即清空。

- 路由器上的 USB 打印服务（`p9100d`，监听 9100 端口）**只转发打印数据，不灌固件**；
- 用电脑打印时，惠普驱动会顺手把固件补上 → 所以那之后手机能打；
- 打印机一断电重启，内存里的固件没了 → 手机发的任务石沉大海。

**修复思路**：让路由器在打印机每次接入 USB 时自动补灌一次固件。

## 三、已部署内容

### 3.1 路由器上的文件（都在 `/etc/storage/`，重启不丢）

| 文件 | 作用 |
|---|---|
| `sihp1020.dl` | 打印机固件本体，126,151 字节，MD5 `86403c3b9c64eae8aeb0e68abf5cb5ff` |
| `print1020.sh` | 补灌主程序：`load` 补灌 / `probe` 存活探测 / `watch` 守护 |
| `hp1020_hotplug.sh` | mdev 热插拔钩子（包装了固件原有的 `mdev_lp`） |
| `started_script.sh` | 开机自启：**文件开头（第 6–18 行）**插入了 HP1020 补丁块 |
| `started_script.sh.bak-hp1020` | 改动前的原始备份，回滚用 |

> ⚠️ 补丁块必须放在**开头**，不能放文件末尾：这个固件的 `started_script.sh` 第 75 行会调用 hiboy 的
> `/etc/storage/script_script.sh`，它会联网下载缺失脚本并**反复重试**（实测把后面的内容堵了约 70 秒）。
> 放末尾会导致路由器刚开机的一分多钟内补丁没打上。

### 3.2 `/etc/mdev.conf` 的改动（关键）

`/etc` 是内存盘，`/etc/mdev.conf` 每次开机由固件重新生成，所以**每次开机都要重新打补丁**（已写进开机自启块）。

改动是把固件原有的打印机热插拔处理**替换**（不是追加）为我们的钩子：

```diff
- usb/lp[0-9] 0:0 0660 */sbin/mdev_lp $MDEV $ACTION
+ usb/lp[0-9] 0:0 0660 */etc/storage/hp1020_hotplug.sh $MDEV $ACTION
```

> ⚠️ **坑**：busybox 的 mdev **只执行第一条匹配规则**，追加一条同规则的命令是**无效的**（实测证实）。
> 所以必须替换。钩子里第一件事就是调用 `/sbin/mdev_lp`，保证打印服务原有的启停行为不受影响（实测 p9100d 照常重启）。

### 3.3 两条触发通路（双保险）

1. **主通路（秒级响应）**：打印机断电重启 → USB 断开再枚举 → mdev 调用钩子 → 等 8 秒稳定 → 补灌固件
2. **兜底通路（轮询）**：`watch` 守护进程每 6 秒检查 `/dev/usb/lp0` 是否出现/消失，漏事件也能补上；
   顺带每 60 秒自检 `mdev.conf` 补丁是否还在，丢了自动补

### 3.4 灌完必须过"存活校验"

灌完固件后，脚本会向打印机发一条 PJL 命令并读回应答：

```
→ @PJL INFO ID
← HP LaserJet 1020      ← 有这条才算成功（没固件的打印机不会应答）
```

最多重试 3 轮下发 / 每轮 4 次探测，全部失败才放弃。

> ⚠️ **设备占用要当心**：usblp 驱动**同一时刻只允许一个写者**。若打印机正被占用（有打印任务在跑），
> 探测会返回「状态未知」而不是「无应答」——此时**不会重复灌固件**，避免把固件反复刷进打印机。
> 探测返回值：`0`=有应答、`1`=无应答（固件缺失）、`2`=设备被占用状态未知。

## 四、运维手册

```sh
# 看当前状态（打印机活不活）
/etc/storage/print1020.sh probe

# 手动补灌一次
/etc/storage/print1020.sh load

# 看日志
cat /tmp/hp1020.log          # 脚本自己的日志
grep HP1020 /tmp/syslog.log  # 系统日志里的记录

# 看守护进程在不在
ps | grep '[p]rint1020'
```

**正常日志长这样**：

```
[hotplug] MDEV=usb/lp0 ACTION=add
热插拔: 检测到打印机 USB 接入, 8 秒后补灌固件
补灌成功并通过存活校验 (USB devnum 4, 第1轮下发/第2次探测)
```

**改动文件后一定要固化到闪存**，否则重启会还原：

```sh
/sbin/mtd_storage.sh save
# 或在网页后台：高级设置 → 系统管理 → 恢复/导出/上传设置 → 保存 /etc/storage/ 内容到闪存
```

**回滚**（万一想撤掉）：把 `started_script.sh.bak-hp1020` 覆盖回 `started_script.sh`，
再 `mtd_storage.sh save`。`/etc/mdev.conf` 不用管，重启会自动恢复成原厂规则。

## 五、踩过的坑（下次别重复）

| 坑 | 说明 |
|---|---|
| mdev 只跑第一条匹配规则 | 追加规则无效，必须替换 `/sbin/mdev_lp` |
| `/etc` 是内存盘 | `mdev.conf` 改动开机必丢，必须写进开机自启 |
| 僵尸锁 | 补灌进程被中途杀掉会留下 `/tmp/hp1020.lock`，永久阻塞后续补灌 → 已改成 PID 存活检测 + 180 秒超时自愈 |
| busybox `ps` 截断命令名 | `ps` 里显示成 `...print1020.sh wat`，按命令行匹配杀进程会失效，用 `killall print1020.sh` |
| busybox `sleep` 不支持小数 | `sleep 0.2` 直接报错，只能用整数秒 |
| 写成功 ≠ 打印机活了 | 必须用 PJL 应答校验，否则可能"以为成功其实没生效" |
| `mtd_storage.sh` 的雷 | 若 `started_script.sh` 里丢了 `/etc/storage/script_script.sh` 这一行，固件会**重置全部自定义脚本**，编辑时必须保住它（已校验 3 次） |

## 八、附：停用 hiboy 脚本链（2026-09-28）

### 8.1 为什么动它
这个 Padavan 是 hiboy（H大）版，`started_script.sh` 里挂着 hiboy 的扩展脚本体系。
它每次开机都会：

1. 跑 `/etc/storage/script_script.sh` → 调 `sh_upscript.sh` / `sh_opt_script_check.sh`，
   去 `opt.cn2qq.com`、`raw.githubusercontent.com` **比对 MD5 并自动下载缺失的 Sh*.sh / 扩展页文件**；
2. 网络不通时**反复重试**，把后面的启动内容**堵了约 70 秒**；
3. 后台还跑 `/etc/storage/www_sh/menu_title.sh`（`check_www_sh`），同样会联网下载 `Advanced_Extensions_*.asp`。

而实际检查下来：**hiboy 的功能开关全是 0**（adbyby / koolproxy / ss / v2ray 等一个都没启用），
`script0_script.sh`（自定义脚本0）里也没有任何自定义内容。**停掉它没有任何功能损失。**

### 8.2 改了什么（只注释调用，不删文件）
| 位置 | 改动 |
|---|---|
| `started_script.sh:27` | `/etc/storage/www_sh/menu_title.sh &` → 注释掉（停掉 www_sh 联网下载） |
| `started_script.sh:75` | `/etc/storage/script_script.sh` → 注释掉（停掉 Sh*.sh 自动更新） |

> 🔴 **雷点**：第 75 行**必须保留那串路径字样**（写成注释即可）。
> `mtd_storage.sh` 会 `grep /etc/storage/script_script.sh /etc/storage/started_script.sh`，
> 一旦匹配不到，它会判定"缺少关键启动命令"并**重置全部自定义脚本**——HP1020 的补丁块也会一起没。
> 实测注释后字串仍能匹配（`grep -c` = 1），安全。

### 8.4 保留的东西

## 九、附：Windows 电脑添加这台网络打印机

### 9.1 为什么「添加打印机」搜不到
Padavan 的打印服务（`p9100d` 900 端口 / `lpd` 515）只是个**裸转发器**，
**不做 WSD / mDNS / Bonjour 广播**，所以 Windows「添加打印机」向导的自动搜索**永远找不到它**。
只能手动建端口——这是正常现象，不是故障。

### 9.2 正确添加步骤
1. 设置 → 蓝牙和其他设备 → 打印机和扫描仪 → 添加设备 → **「我需要的打印机不在列表中」**
2. 选「使用 IP 地址或主机名添加打印机」（或手动设置 → 创建新端口）
3. 设备类型 TCP/IP，主机名/IP：`192.168.2.120`，端口 `9100`（RAW），可取消勾选"查询打印机"
4. 驱动：厂商 HP → **HP LaserJet 1020**（本机已装）
5. 完成后：打印机属性 → **端口** 选项卡 → **取消勾选「启用双向支持」** ← 关键一步

### 9.3 本机实际配置（2026-09-28 已配好，可直接用）
| 项 | 值 |
|---|---|
| 打印机名 | HP LaserJet 1020 无线打印（已设为默认） |
| 驱动 | HP LaserJet 1020 |
| 打印处理器 | HP1020PrintProc |
| 数据类型 | IMF |
| 端口 | Standard TCP/IP @ `192.168.2.120`，RAW，9100，SNMP 关闭 |
| 双向支持 | 关闭（注册表 Attributes = 0） |

### 9.4 坑 A：错误码 1803「打印机命令无效」
Windows 事件日志（Microsoft-Windows-PrintService/Admin）出现：

```
无法在打印机 HP LaserJet 1020 上打印。数据类型: RAW。打印的字节数: …。打印页面总数: 0。
打印处理器返回的 Win32 错误代码: 1803。打印机命令无效。
```

= **宿主型(GDI)打印机没拿到固件**（本机历史记录：9/2、9/11、9/22、9/25 多次，全部 0 页）。
现在固件由路由器自动补灌，再配合「关闭双向支持」即可正常打印。

### 9.5 坑 B：测试页被重复发送 66 次（本项目实际踩到）
在**开着「启用双向支持」**的打印机对象上发测试页，路由器日志出现：

```
p9100d: Finished job: 28125/28125 bytes sent to printer   ← 每秒约 10 次，累计 60+ 次
```

打印机**连续吐纸**。原因：裸 9100 端口无法回答驱动的状态查询，后台处理程序反复重启该任务。
**处置**：取消任务 → 清空队列 → 关闭「启用双向支持」。

> 🔴 **连带影响**：任务取消后 `p9100d` 可能卡在 **D 状态**（USB 写阻塞），
> 且若打印机缺纸/阻塞，`/dev/usb/lp0` 的写操作会**永久阻塞**——我们的固件补灌也会被堵住（`cat` 卡在 D 状态）。
> 解法：给打印机**断电重启**；或软件复位 USB：
> `echo -n 1-1 > /sys/bus/usb/drivers/usb/unbind && sleep 2 && echo -n 1-1 > /sys/bus/usb/drivers/usb/bind`
